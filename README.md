# 随身收件箱 · Pocket SMS

**无需账号，本地部署，数据留在自己的设备上。**

让备用机B把收到的短信上传到你自己的电脑、NAS或安卓设备，再用常用手机A的浏览器查看。每个人部署各自的实例，各有自己的数据库和配对密钥，程序没有公共收件服务器。

- 去掉了ChatGPT登录、云数据库、Bark和第三方推送依赖。
- 服务端仅用Node.js内置模块，零第三方运行依赖，不需要`npm install`或构建。
- 页面在前台时每2秒检查一次新短信，支持多备用机、SIM卡槽、搜索和验证码复制。
- B用上传密钥，A用查看链接；无需注册、用户名、密码或外部账号。
- 默认短信保存24小时，可配置；可以删除短信、撤销配对。
- MIT开源许可，可自行修改、部署和分发。

## “完全本地”是什么意思？

短信存入**运行本程序那台设备**的`data/inbox.sqlite`，不是上传给项目作者，也不是存到一个大家共用的网站。

| 场景 | 数据放在哪里 | 谁能看到 |
| --- | --- | --- |
| 小明在自己电脑部署一份 | 小明电脑的数据目录 | 小明本机及其配对的A手机 |
| 小红在自己NAS部署另一份 | 小红NAS的独立数据目录 | 小红的管理设备及其配对的手机 |
| 同一个实例配对两台查看手机 | 同一个实例的数据库 | 两台手机能看到该实例的全部短信 |

不同实例不会互相发现、同步或共享数据。请为不同人的实例使用不同数据目录，不要复制他人的数据库或密钥文件。**“本地”不等于离开家后无需网络：出门查看必须能连回自己的部署设备。**

## 快速开始

### 1. 安装Node.js 24或更新版本

从[Node.js官网](https://nodejs.org/)安装。终端执行`node --version`确认版本至少为24。

下载并解压本项目，在项目目录打开终端：

```bash
node server.mjs --lan
```

Windows也可双击`start-lan.bat`；macOS/Linux可运行：

```bash
sh start-lan.command
```

打开**部署设备本机**的`http://127.0.0.1:3210`。本机无需登录；程序关闭后网页服务也会停止。

只想先在电脑本机试用、不接受其他设备连接：

```bash
node server.mjs
```

### 2. 接入B手机

B需要是能够运行[SmsForwarder短信转发器](https://github.com/pppscn/SmsForwarder)的安卓手机。

在本机网页点击“接入B手机”，填写名称和**手机能够访问的部署地址**，例如`http://192.168.1.20:3210`。初次测试时让B、A和部署设备连接同一Wi-Fi，并允许系统防火墙在该私人网络接受3210端口连接。

按向导在B端配置：

1. 新建Webhook发送通道，请求方式选POST。
2. 请求地址填向导给出的`http://你的设备地址:3210/api/ingest`。
3. 自定义请求头新增一项：名称`X-Upload-Key`，值填向导生成的密钥。
4. 请求参数填向导给出的表单模板；加签Secret留空。
5. 保存，并将短信转发规则绑定到这个通道。双卡请检查规则范围。
6. 向B号码发一条普通测试短信，确认本地网页收到。

配对配置只显示一次。密钥遗失时撤销旧配对、重新生成即可。

### 3. 让A手机查看

在部署设备本机网页点击“在A手机上查看”，生成查看链接。在A的浏览器打开此链接即可，无需账号。

链接带有随机密钥，只授权读取该实例的短信。密钥经URL片段传入，网页读取后从地址栏移除，仅保存在此标签页的会话中；短信不写入浏览器的持久存储。新会话需重新打开原配对链接。不要分享密钥链接。

### 4. 出门后继续查看

局域网IP（例如`192.168.x.x`）通常只能在家中网络访问。外出查看可使用你自己的私人组网/VPN，让A连接回部署设备；B如果也在外面，需要同样能够连接上传地址。

本项目不提供公共中转、在线账户或自动穿透。也可以自行用HTTPS反向代理暴露服务，详见[部署说明](docs/deployment.md)。不要把普通HTTP接口直接暴露到公网，密钥和短信需要受保护的传输链路。

## Docker / NAS

安装Docker后，在项目目录运行：

```bash
docker compose up -d --build
```

容器数据保存在本机的`inbox-data`卷，不会发送到外部数据库。容器网络不会自动被视为本机管理员；请在部署设备终端生成管理配对链接：

```bash
docker compose exec inbox node tools/admin-link.mjs http://127.0.0.1:3210
```

把输出链接在部署设备浏览器打开，即可管理配对。若从另一台管理电脑打开，把命令最后的地址改为NAS的局域网IP。这个链接有管理权限，请保密。

运行`docker compose down`保留数据；`docker compose down -v`会删除数据库所在卷。当前交付已测试Node方式，Docker配置未在本开发环境实际构建（环境没有Docker）。

## 常用配置

| 配置 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` / `--host` | `127.0.0.1` | 仅本机；`--lan`改为`0.0.0.0` |
| `PORT` / `--port` | `3210` | HTTP端口 |
| `DATA_DIR` / `--data-dir` | 项目内的`data/` | SQLite和管理密钥目录 |
| `RETENTION_HOURS` | `24` | 短信保留小时数，1到8760 |
| `PUBLIC_URL` / `--public-url` | 空 | 自定义域名或代理地址，不带路径 |

可以复制`.env.example`为`.env`，然后显式加载：

```bash
node --env-file=.env server.mjs
```

优先级：命令行参数高于环境变量。若设置`HOST`，其优先级高于`--lan`快捷开关。配置中没有任何云平台API密钥。

## 数据与备份

- 数据目录包含SQLite数据库、可能存在的SQLite WAL文件和`management-key.txt`。这些文件永远不要提交到开源仓库。
- 备份前停止程序，再复制整个数据目录。恢复时停止程序，用备份替换数据目录后再启动。
- 配对密钥在数据库中仅存SHA256摘要；管理密钥文件用于容器管理配对。丢失管理密钥时，在部署设备移除`management-key.txt`并重启即可生成新密钥，旧管理链接失效。
- 服务运行时每分钟清理过期短信，读取和上传时也清理。停止服务期间不执行定时清理，重启后补清理。
- 数据库是本地明文文件，拥有设备文件访问权限的人可以读取它；配对链接也应像家门钥匙一样保管。

## 已有功能与边界

B收到短信 → B转发器上传 → 本地SQLite → A网页每2秒检查。

页面前台刷新间隔是2秒，**不是整条链路“2秒内必达”的承诺**。B端短信读取、系统后台限制、网络断开或上传失败仍会造成延迟。A锁屏或切到后台后，浏览器可能暂停刷新。本项目不提供锁屏推送、短信回复和电话接听，也不会主动拉取B手机历史短信。

本项目目前使用现有SmsForwarder作为B端上传器，尚未包含独立安卓APK。

## 开发与测试

```bash
npm test
npm run check
```

测试覆盖：本机免账号管理、远程查看配对、仅上传权限、CSRF与Host校验、真实HTTP上传、中文和特殊字符、重试去重、双实例数据/密钥隔离、重启持久化、过期清理和配对撤销。所有测试都使用临时数据目录，不接触真实短信。

项目没有遥测、统计SDK、CDN、第三方字体、云端API或开机自动更新请求。静态资源全部随源码提供。上传协议与开发细节见[API说明](docs/api.md)。
